## Authoritative processing

A private partner/environment lease is acquired before subscription/invoice/charge reads; monotonic fences plus a two-minute lease reject timed-out workers after another instance takes over. All webhook, reconcile and owner provider operations share this lock. Event identity is environment+ID+fingerprint, with immutable partner mapping, attempt count and sanitized failure code. SQL `batch` atomically commits all subscription/addon transitions, event completion and audit; thrown validation rolls the whole batch back. Failure recording/retry is separate. Duplicate event identity does not add quota or transitions; event-created order is not used as state truth.

Provider snapshot uses installed Stripe22.3.2 / `2026-06-24.dahlia`, item-level periods, invoice parent.subscription_details and paginated line/payment relationships. A known single licensed month/year item matching its offer, quantity1, pinned exact EUR amount/tax/environment/customer, paid invoice and successful unrefunded/undisputed charge establish active rights. Active flag, zero/manual/out-of-band invoice, browser return, metadata or unknown price never grants Pro. Existing pinned deactivated Stripe prices are allowed for an existing contract, new checkout requires active price. Unknown items, discounts, pause_collection and unrecognized subscription schedules fail closed. Only the exact pinned Founder schedule is supported. Trials require confirmed actual activation and the original or explicitly requested earlier free-phase end. Reconciliation reads the latest contract per base/addon family; old subscription events cannot overwrite its successor.

Refund or dispute on the current paid invoice yields unpaid; historical events cause a new authoritative current-state evaluation rather than blindly revoking a later paid period. Any partial refund is conservatively unpaid pending review. No automatic refunds/credits are issued. A valid subsequent payment/current active state recovers rights. Initial incomplete/expired unacknowledged trial never gets grace. For a previously paid continuing period, first failure uses provider invoice finalization time (bounded by current time), subsequent failures retain the same DB past_due_since. Old disconnected paid-through cannot create a fresh episode. Only valid active payment clears it; central resolver expires seven days exactly, independently of job delivery. Records, earned rewards, orders and existing data are not deleted by downgrade; existing quota triggers block new over-limit activation without randomly suspending staff.

## Provider cancellation recovery (review fix)
Cancellation mutations acquire a durable per-partner barrier before rereading the authoritative base. SQL stores the exact subscription/contract target, operation, parameters and idempotency key before dispatch. Expired workers cannot authorize a new order. Lease turnover permits only recovery of the saved order before normal reconciliation; it never derives a replacement target or parameters. An unknown transport outcome retains this barrier. A timeout does not imply Stripe stopped processing.

Supported operations are monotone cancellation only: immediate cancellation without invoice/proration, or the saved cancellation date/period end. Portal updates/resumption are disabled. Replaying an identical order after idempotency retention cannot restore renewal or target a replacement subscription. A definitive current provider cancellation outcome resolves the order; unknown targets/errors stay blocked and audited. The authenticated reconcile job retries these orders. Owners can explicitly retry through **Abrechnungsstatus prüfen / offenen Auftrag fortsetzen**; the shared billing summary shows unresolved recovery to owners and Admins. Prepared orders without dispatch authorization can be discarded, then fresh evidence is read. Recovery acquisition, resolution and failures have audit entries.

## Founder recovery and Admin operating paths

Admin → partner → Einstellungen → Tarif & Module remains the operating surface. An overdue unbound activation requires the administrator to inspect the original Stripe request log and provide its `req_...` reference, documentary reason and explicit terminal-failure attestation. Time elapsed, a timeout or an empty list alone is insufficient. The server independently lists this customer's schedules/subscriptions again; any matching object forces reconciliation instead of closure. `admin_close_failed_founder_activation` requires that recent check and the current Admin role, retains the expired intent/audit, releases only its unaccepted seat, and never manufactures activation. A later event cannot bind/apply/activate the expired intent. Unexpected matching provider objects reopen a visible billing review without admission/rights; the Admin must stop them in Stripe and inspect invoices/payments. The dedicated review action verifies no matching active schedule/subscription remains, then records the Admin's invoice/correction evidence. No hidden timed unlock exists.

For a timely trial exit rejected after the provider already transitioned, the persisted exact order survives. Recovery stops future renewal of that same known subscription without a final invoice/proration, marks an invoice/payment review, and cannot grant the paid minimum term from a late paid snapshot. The Admin panel shows received/agreed dates and audit/provider references. The administrator reviews the first invoice/payment in Stripe, voids an unentitled open invoice where appropriate, or applies the separately verified agreed correction for a paid amount; no refund is invented or automatically issued. The Admin **Abrechnungsprüfung protokollieren** action requires a confirmed canceled provider state and documentary evidence. Remaining checks are release-gated hosted acceptance, not a claim of atomic DB+Stripe transactions.
